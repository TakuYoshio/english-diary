## 🚧 今の作業: ログイン機能の追加

Supabase URL・Anon Key・合言葉の手入力をなくし、代わりにメール＋パスワードでログインする方式に変更中です。以下、あなたにお願いしたい作業です。

---

### 1. Supabase Project URL と anon key を教えてください

Supabaseダッシュボード → 対象プロジェクト → **Settings → API** を開き、

- **Project URL**（`https://xxxx.supabase.co`）
- **anon public** キー（`eyJ...`。"anon"「public」と書かれている方。**service_role キーは絶対に使わない・共有しない**）

の2つをチャットで教えてください。anon keyは公開されても安全な設計のキーなので、そのまま貼って大丈夫です。

---

### 2. SQL移行を実行

`Task/supabase-migration.sql` を用意しました。Supabaseダッシュボードの **SQL Editor** に中身をコピペして実行してください。

内容：
- `entries`・`vocab`テーブルの中身を削除（テストデータのみとのことなので）
- `user_id`列を追加
- Row Level Security（RLS）を有効化し、「自分の行しか見えない・操作できない」ポリシーを8つ作成

実行後、**Table Editor**で両テーブルに`user_id`列があり、RLSが「Enabled」になっていることを確認してください。

---

### 3. Authentication設定を確認

Supabaseダッシュボード → **Authentication → Providers** で「Email」が有効になっていることを確認。

Authentication → **URL Configuration** で、Site URL / Redirect URLsに実際のGitHub Pages URL（例: `https://takuyoshio.github.io`）を追加してください。

---

### 4. 一緒に使う人を招待

Authentication → **Users** → **Invite user** から、あなた自身と、一緒に使いたい人のメールアドレスを一人ずつ招待してください。招待された人にはメールが届き、パスワードを設定するとログインできるようになります。

**アプリ内には「新規登録」フォームは作りません**（誰でも自由に登録できるとGeminiの無料枠を消費されるリスクがあるため）。新しい利用者は必ずこの招待経由で追加してください。

---

### 5. （こちらで実施）コード側の変更

上記1〜4が終わったら、こちらで以下を進めます：
- `app.js`・`index.html`をログイン画面に作り替え
- Cloudflare Workerの合言葉ゲートを「ログイン済みユーザーかどうかの検証」に置き換えて再デプロイ
- 古い`APP_PASSCODE`シークレットの削除
- 動作確認（2つのアカウントでデータが分離されているかなど）

---

## 注意点

- `service_role`キーは絶対にどこにも貼らない・使わない（RLSを無視して全データにアクセスできてしまう強い権限のキーのため）
- 招待制なので、これまで共有していた「合言葉」は今後不要になります
