## ① コトラとAI会話（Kotora Talk）

### 概要
自分が書いた日記の内容をネタに、コトラが英語で話しかけてくる会話練習モード。
「昨日カフェに行ったんだよね？どうだった？」のように **自分の生活に基づいた対話** なので、汎用英会話アプリと違い返答が"自分ごと"になる。

### UXフロー
1. ホームに「コトラとおしゃべり」ミッションカードを追加（1日1回）
2. タップでチャット画面へ（新規タブ `tab-talk` またはモーダル）。上部にコトラ（`kotoraImg`）、下に吹き出しチャットログ
3. 開始時: 直近の日記1〜3件の `corrected`（添削済み英文）をコンテキストにGeminiが最初の質問を生成
   - 例: 日記に "I went to a café" → コトラ: "You went to a café yesterday! What did you order?"
4. ユーザーは音声（既存 `SpeechRecognition` 流用）またはタイピングで英語返答
5. コトラが「自然な返し + さりげない言い直し(recast)」で応答。3〜5往復で会話終了
6. 終了時にコトラが会話のまとめ + 使えた表現/惜しかった表現を1つずつフィードバック。XP付与（+10）

### 技術設計
- **AI**: 既存の `callGemini`（app.js）と Cloudflare Worker プロキシをそのまま利用。会話履歴を `contents` の multi-turn 形式で送る
- **プロンプト方針**: system指示に「CEFR A2-B1相当の簡単な英語 / 1返答は2文以内 / 質問で終える / recastを含める」。`responseSchema` で `{ reply, recast_hint }` のJSON構造化
- **レート制御**: 1日1会話・最大6往復をフロントで制限（`localStorage: kotoraTalk:<date>`）。既存Workerのリトライ機構を流用
- **表示**: コトラ側の吹き出しは `kotoraSay` を拡張するのではなく、チャットログ用の静的吹き出しCSS（`.kt-bubble` の変種 `.kt-chat-bubble`）を新設。mood連動は `mascotSetMood('talk-mascot', ...)`
- **保存**: 会話ログはSupabaseに保存しない（v1はセッション限り）。まとめのフィードバックだけ `entries.feedback` とは別に残したければ将来 `talks` テーブルを検討

### 変更ファイル見込み
- `index.html`: `tab-talk` セクション + ナビ項目（またはホームからのモーダル）
- `app.js`: 会話ロジック `startKotoraTalk()` / `sendTalkReply()`（約150行）
- `kotora-speech.js`: チャット用セリフキー追加（開始/終了の定型文）
- `style.css`: チャットUI（約80行）
- `worker/src/index.js`: 変更不要（既存エンドポイント流用）

### 工数目安: 大（UI新設 + プロンプト調整の反復が必要）

## ② 過去日記から復習出題（Diary Quiz）

### 概要
自分が書いた過去の日記の添削済み英文（`entries.corrected`）から穴埋め・並べ替え問題を自動生成する。
**自分の言葉・自分の出来事** だから記憶に定着しやすく、書きっぱなしの日記が資産になる。

### UXフロー
1. テストタブのモード切替に「日記から復習」を追加（既存: 単語テスト / 状況文で練習）
2. 出題形式（AIなしでローカル生成できる2形式）:
   - **穴埋め**: correctedの1文からキーワード（単語帳 `vocab.en` と一致する語 > 動詞/形容詞）を1つ隠して入力させる。「あなたの2026-08-01の日記より」と日付を添える
   - **並べ替え**: correctedの1文（5〜10語）を単語シャッフルしてタップで並べる（Duolingo方式）
3. 正誤判定は既存の `normalizeAnswer` 系ロジック（NFKC・編集距離）を流用
4. 正解時に元の日記全文を「思い出しカード」として表示（日本語原文 + 英文）→ 記憶のフックにする
5. コトラのリアクションは既存 `mascotReactQuiz` / `kotoraSay('quiz-ok'/'quiz-ng')` がそのまま使える

### 技術設計
- **出題元の選定**: `entries` から `corrected IS NOT NULL` を新しい順に20件取得 → 文分割（`. ` split）→ 5〜12語の文だけ採用
- **穴埋め対象語の選定優先度**: ①単語帳に登録がありSRS期限切れの語 ②単語帳登録語 ③4文字以上の内容語（冠詞/前置詞/be動詞を除外するstopword listを定数で持つ）
- **並べ替えUI**: 選択肢チップをタップ→回答欄に積む方式。`quiz-choices` のCSSパターンを流用
- **SRS連動**: 穴埋めで単語帳の語を出題した場合は既存 `updateVocabSrs`（正解+1/不正解-2ステージ）を呼ぶ
- **AI不要・完全ローカル生成**（運用費0円の制約C-03を維持）

### 変更ファイル見込み
- `index.html`: クイズモードトグルに3つ目のボタン + 出題エリア（約40行）
- `app.js`: `buildDiaryQuizPool()` / `renderDiaryQuiz()` / 判定（約180行）
- `style.css`: 並べ替えチップUI（約40行）
- DB変更: なし

### 工数目安: 中

## ③ SRS可視化 + 苦手単語特訓（Word Garden）

### 概要
単語ごとの記憶ステージ（`vocab.srs_stage` 0〜6）を「芽→双葉→つぼみ→花」の成長で可視化し、覚えるほど庭が育つ。
さらに正答率の低い単語だけを集中的に出題する「苦手特訓モード」を追加。SRSが「賢く出題されている感」を見せる。

### UXフロー
1. **単語帳タブ**: 各単語カードに成長アイコンを表示
   - stage 0-1: 🌱 / stage 2-3: 🌿 / stage 4-5: 🌷 / stage 6: 🌸（絵文字でよい。将来SVG化可）
   - タップで「次の復習日: 8/23（あと3日）」のツールチップ
2. **単語帳ヘッダー**: 「🌸12 🌷8 🌿15 🌱20」のサマリーチップ + 「苦手 5語」バッジ
3. **苦手特訓モード**: テストタブに「苦手単語だけ」トグル
   - 対象: `wrong >= 2 かつ 正答率 < 60%` の単語（該当0件なら非表示）
   - 出題は既存の3形式（タイピング/4択/リスニング）をそのまま使い、絞り込みだけ変える
   - 特訓で2回連続正解したら「苦手」から卒業 → コトラが `kotoraSay` で祝う
4. **ホームミッション**: 「復習する単語」カードに🌱アイコンと期限切れ内訳を追加表示

### 技術設計
- 成長段階は表示時に `srs_stage` から算出（新カラム不要）: `stageEmoji(stage)` ヘルパーを `app.js` に追加
- 苦手判定: `isWeakWord(v) = v.wrong >= 2 && v.correct / (v.correct + v.wrong) < 0.6`（既存の正答率色分けロジックの隣に置く）
- 「2回連続正解で卒業」のために `vocab` に **`win_streak int default 0`** を追加（唯一のDB変更）
  - マイグレーション: `Task/add-vocab-win-streak.sql` → `alter table vocab add column win_streak int not null default 0;`
  - 既存の正誤更新処理（`updateVocabSrs` 付近）で正解時 `+1` / 不正解時 `0` リセット
- クイズの出題プール構築（`buildQueue` 相当）に `weakOnly` フラグを追加

### 変更ファイル見込み
- `app.js`: stageEmoji / isWeakWord / 出題フィルタ / 単語カード表示（約100行）
- `index.html`: トグルボタン + サマリーチップ（約15行）
- `style.css`: チップ・ツールチップ（約40行）
- `Task/add-vocab-win-streak.sql`: 新規

### 工数目安: 小〜中（最初に着手するのに最適）

## ④ ウィークリーレポート（コトラの週報）

### 概要
週の終わり（または月曜の初回起動時）に、コトラが先週1週間の頑張りをストーリー仕立てで振り返ってくれる画面。
「見えなかった努力の可視化」を週単位で締めることで、継続のモチベーションを作る。

### UXフロー
1. 週が明けて初めてホームを開いたとき、コトラが `kotoraSay` で「先週のレポートができたよ📮」→ タップでレポートモーダル表示（`mascot-modal` と同じモーダル基盤）
2. レポート構成（カード縦積み、1画面スクロール）:
   - ヒーロー: コトラ（happy/delighted）+「先週は◯日書けたにゃ！」
   - 数字カード: 書いた日記 ◯件 / 新しい単語 ◯語 / クイズ正解 ◯問 / 発音ベスト ◯点（`animateNumber` でカウントアップ）
   - ハイライト: 先週の日記から1文引用（最長 or 発音スコア最高の日）「この文、良かったにゃ」
   - 今週のひとこと: ストリーク状況に応じた定型応援メッセージ（ローカル辞書。AI不要）
3. 「今週もがんばる🔥」ボタンで閉じる → confetti
4. 過去レポートの再閲覧: 履歴タブの統計ビューに「週報を見る」リンク（常に直近週を再生成）

### 技術設計
- **完全ローカル集計**: `entriesMeta` / `allVocab` から先週分（月〜日）をフィルタして集計。新テーブル不要
  - 集計関数 `computeWeeklyReport(weekStartISO)` を `progress.js` に追加（`computeStreaks` / `computeXp` と同居）
- **表示済み管理**: `localStorage: weeklyReport:<週の開始日>` で「その週のレポートを見たか」を記録（未読なら起動時に通知）
- **引用文の選定**: 対象週の `entries.corrected` から最も長い1文（または `pronunciation_first_attempt.score` 最高の文）
- AI呼び出しなし（コトラの講評はセリフ辞書 `KOTORA_LINES` に `weekly-*` キーを追加してバリエーション対応）

### 変更ファイル見込み
- `progress.js`: `computeWeeklyReport()`（約60行）
- `app.js` or 新規 `weekly.js`: モーダル描画 + 未読チェック（約100行）
- `kotora-speech.js`: `weekly-great` / `weekly-good` / `weekly-comeback` 等のセリフ追加
- `index.html`: モーダル1つ追加（約20行）
- `style.css`: レポートカード（約60行）
- DB変更: なし

### 工数目安: 中

## 共通の注意事項（実装時に必ず守る）

- **変数名凍結**: 既存のCSS変数名・関数名・mood名・data属性は変更しない。追加のみ
- **コーラルパレット維持**: 新UIも `--accent` / `--secondary` / `--gold` のトークンから組む
- **モバイルファースト**: 768px以下のボトムタブバー・ボトムシートの流儀に合わせる
- **運用費0円**: AIを使うのは①のみ。②③④はローカル計算で完結させる
- **i18n**: UI文言は `TRANSLATIONS` へ、コトラのセリフは `KOTORA_LINES` へ（混ぜない）
- **prefers-reduced-motion**: 新規アニメーションは必ず既存のreduced-motionガードに追記
