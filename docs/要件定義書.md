## 2. プロジェクト概要

### 2.1 目的

「読む・聞く」中心になりがちな英語学習を、**書く（英作文）・話す（発音）のアウトプット中心**の習慣に変える。毎日の日記を題材に、自力での英訳 → 語彙調査 → 再英訳 → AI 添削 → シャドーイング → 発音チェックという一連のサイクルを 1 つのアプリで完結させる。

### 2.2 背景

- 単なる翻訳アプリでは「自分で考えて書く」プロセスが省略され、学習効果が薄い
- 添削・発音練習・単語帳・テストが別々のツールに分散していると継続しにくい
- 無料枠の外部サービス（Gemini API / Supabase / GitHub Pages / Cloudflare Workers / Web Speech API）を組み合わせることで、**運用費 0 円**で実現できる

### 2.3 ターゲットユーザー

- **招待制の複数ユーザー**（本人＋招待した相手）。Supabase Auth により、ユーザーごとにデータが分離される
- 想定レベル：日本語話者の英語学習者（初級〜中級）
- 利用端末：Mac / iPhone などのブラウザ（iPhone は「ホーム画面に追加」で PWA ライクに利用）

### 2.4 スコープ

- 対象：ユーザー認証（招待制）、日記作成の学習フロー、AI 添削、音声再生・発音チェック、単語帳、単語テスト、間隔反復（SRS）、シチュエーション文練習、UI 言語切り替え、学習設定（オンボーディング／個人設定）
- 対象外：新規ユーザーのセルフサインアップ、オフライン動作、ネイティブアプリ化

## 3. システム構成

### 3.1 構成概要

サーバーサイドの永続コードを持たない**静的シングルページアプリケーション（SPA）**。AI 呼び出しのみ、認証情報を検証する薄いプロキシ（Cloudflare Workers）を経由する。

```
┌──────────────────────────────────────────────────────┐
│  ブラウザ（GitHub Pages で配信される静的 SPA）          │
│  index.html / style.css / app.js                     │
│  ├─ localStorage（UI 言語・クイズモード等の軽量な状態） │
│  ├─ Web Speech API（TTS / 音声認識）※内蔵             │
│  │                                                   │
│  ├──→ Supabase Auth（メール＋パスワード、招待制）        │
│  │                                                   │
│  ├──→ Cloudflare Worker（Bearer トークン検証）          │
│  │      └──→ Gemini API（gemini-3.5-flash）           │
│  │             英文添削・フィードバック・単語検索・       │
│  │             発音アドバイス・シチュエーション文生成/採点 │
│  │                                                   │
│  └──→ Supabase（PostgreSQL、RLS 有効）                 │
│         entries（日記）/ vocab（単語帳）/ profiles（設定）│
└──────────────────────────────────────────────────────┘
```

### 3.2 技術スタック

| 区分 | 技術 | 用途 |
|------|------|------|
| フロントエンド | HTML / CSS / Vanilla JavaScript | 画面・全ロジック（ビルド工程なし） |
| ホスティング | GitHub Pages | 静的ファイル配信 |
| 認証 | Supabase Auth（メール＋パスワード） | 招待制ログイン。アプリ内に新規登録フォームは存在しない |
| データベース | Supabase（PostgreSQL, supabase-js v2 CDN、Row Level Security 有効） | 日記・単語帳・ユーザー設定の永続化、ユーザーごとのデータ分離 |
| AI プロキシ | Cloudflare Workers | Gemini API 呼び出しをプロキシし、Supabase セッションの Bearer トークンを検証してから中継。API キーはサーバー側シークレットとして保持 |
| AI 添削・生成 | Google Gemini API（`gemini-3.5-flash`） | 英文添削・フィードバック・単語自動検索・発音アドバイス・シチュエーション文生成/採点 |
| 音声合成（TTS） | Web Speech API `speechSynthesis` | 添削後英文・単語の読み上げ |
| 音声認識 | Web Speech API `SpeechRecognition` | 発音チェック、シチュエーション文練習での発話回答 |
| フォント | Google Fonts（Inter / Noto Sans JP） | UI 表示 |

### 3.3 画面構成

| 画面 | 内容 |
|------|------|
| ログイン画面 | メールアドレス・パスワードでログイン。新規登録 UI はなく、Supabase ダッシュボードからの招待でのみアカウントが発行される |
| オンボーディングモーダル | 初回ログイン時に表示。伸ばしたいスキル・シャドーイングレベル・単語自動検索の設定を行う |
| 日記タブ | 6 ステップの学習フローカード |
| 過去の日記タブ | 検索・ページネーション付きの一覧、日記詳細タブへの遷移 |
| 日記詳細タブ | 過去日記の日本語・英訳 1 回目・2 回目・AI 添削文・カテゴリ別フィードバック・初回発音結果の表示、インライン編集、発音再チェック |
| 単語帳タブ | 単語の追加・一覧・削除・編集・検索・正答率表示 |
| テストタブ | 「単語テスト」「状況文で練習」の 2 モード切替式。単語テストはタイピング／4 択／リスニングの 3 形式、状況文練習は AI 生成シチュエーションへの発話/タイピング回答 |
| 設定モーダル | ログイン中アカウント表示、学習設定（スキル・シャドーイングレベル・単語自動検索）の変更、ログアウト |

## 4. 機能要件（実装済み）

### F-01 認証・ログイン

| ID | 要件 |
|----|------|
| F-01-1 | ログイン画面でメールアドレス・パスワードを入力し、`Supabase Auth`（`signInWithPassword`）で認証する |
| F-01-2 | アプリ内に新規登録フォームは実装しない。新しい利用者は Supabase ダッシュボード（Authentication → Invite user）から運用者が個別に招待する |
| F-01-3 | ログイン済みセッションがあれば自動的にアプリ画面へ遷移する。設定モーダルからログアウトできる |

### F-02 オンボーディング・個人設定

| ID | 要件 |
|----|------|
| F-02-1 | 初回ログイン時（`profiles.onboarding_completed` が false）、オンボーディングモーダルを自動表示し、伸ばしたいスキル（文法／語彙／表現・自然さ／発音、複数選択可）・シャドーイングレベル（Easy 10 回／Normal 20 回／Hard 50 回）・単語の AI 自動検索 ON/OFF を設定する |
| F-02-2 | 設定内容は `profiles` テーブルに保存し、設定モーダルからいつでも変更できる |
| F-02-3 | シャドーイングレベルは Step 6 のシャドーイング回数ゲート（F-06）の目標回数に反映される |
| F-02-4 | スキル重点分野は AI 添削（F-04）でのフィードバックの深掘り分野、および発音アドバイスの詳しさに反映される |
| F-02-5 | 単語自動検索 ON 時、Step 3 の単語入力欄からフォーカスが外れると、日本語↔英語のもう片方を Gemini が自動で埋める |

### F-03 日記作成 6 ステップフロー

各ステップはカード UI で表示され、前のステップを完了するまで次のカードはロック状態とする。

| ID | ステップ | 要件 |
|----|---------|------|
| F-03-1 | ① 日本語で日記を書く | 当日日付を表示し、日本語で自由記述。未入力時は次へ進めない |
| F-03-2 | ② 自力英訳（1 回目） | ①の日本語を参照表示した状態で、辞書等を見ずに英訳を記入。この画面で「わからない単語」をメモすると、③の単語欄に自動で追加される |
| F-03-3 | ③ わからない単語をメモ | 「日本語 → 英語」の単語ペアを任意個数追加・削除できる。常に空欄の入力行を 1 行だけ維持し、②でのメモや「＋追加」操作は既存の空行があればそこに入る（新規行を無制限に増やさない） |
| F-03-4 | ④ 再英訳（2 回目） | ①の日本語と③で調べた単語をヒント表示した状態で、改善版の英訳を記入 |
| F-03-5 | ⑤ AI 添削 | ④の英文を Cloudflare Worker 経由で Gemini API に送信し、添削結果・フィードバック・修正ポイントを表示（詳細は F-04） |
| F-03-6 | ⑥ シャドーイング・発音チェック | 添削後英文を TTS で再生（F-05）し、音声入力で発音を採点（F-06）した後、日記を保存（F-08） |

### F-04 AI 添削（Gemini API・Cloudflare Worker 経由）

| ID | 要件 |
|----|------|
| F-04-1 | 日本語原文・英訳 1 回目・調べた単語リスト・英訳 2 回目・ユーザーの重点スキルをもとに、**高速添削**（添削後英文のみ）と**詳細フィードバック**の 2 本を並列で Gemini API（`gemini-3.5-flash`）に送信する |
| F-04-2 | Gemini 呼び出しはブラウザから直接行わず、Cloudflare Worker を経由する。Worker は `Authorization: Bearer <Supabaseアクセストークン>` を Supabase の `/auth/v1/user` エンドポイントで検証し、ログイン済みユーザーのみ Gemini を呼び出せるようにする。Gemini API キーは Worker のシークレットとしてのみ保持され、ブラウザには渡らない |
| F-04-3 | レスポンスは JSON スキーマ指定（`responseMimeType: application/json` + `responseSchema`）で構造化して受け取る。詳細フィードバックのフィールド：`good_points`（良かった点）／`categories`（grammar・vocabulary・expression・other の 4 分類ごとに要約と修正リスト `before`/`after`/`explanation`（vocabulary は `jp` も含む））／`vocab_usage`（調べた単語の使い方への講評） |
| F-04-4 | ユーザーが選択した重点スキル分野は、該当カテゴリの指摘を厚め（2〜4 件）に、それ以外は簡潔（0〜2 件）にするようプロンプトで指示する |
| F-04-5 | フィードバック文の言語は UI 言語設定（日/英）に追従する |
| F-04-6 | API が 429 または 5xx を返した場合、2.5 秒待って 1 回だけ再試行する |
| F-04-7 | 添削・フィードバックの取得は `Promise.allSettled` で独立して扱い、一方が失敗してももう一方の結果は表示する。添削に失敗した場合は学習者の英文（2 回目）をそのまま添削後英文として扱う |
| F-04-8 | 生成温度は 0.3 とし、出力のばらつきを抑える |
| F-04-9 | 過去日記に保存された旧形式のフィードバック（カテゴリ構造化前の `corrections` フラットリスト）も、専用のレンダラーで引き続き表示できる |

### F-05 音声再生（TTS・シャドーイング）

| ID | 要件 |
|----|------|
| F-05-1 | 添削後英文・単語をブラウザ内蔵の `speechSynthesis` で読み上げる（言語 en-US、速度 0.9 倍、英語ボイスを自動選択） |
| F-05-2 | ステップ⑥に進んだ際、目標文を自動で 1 回読み上げる |
| F-05-3 | 何度でも再生でき、過去日記の詳細ページ・単語テストのリスニング出題からも再生できる |

### F-06 発音チェック（音声認識）

| ID | 要件 |
|----|------|
| F-06-1 | `SpeechRecognition`（en-US、候補 3 件）で学習者の発話を認識する。非対応ブラウザでは警告を表示する |
| F-06-2 | 認識テキストと目標文を正規化（小文字化・アクセント記号除去・短縮形展開・記号除去）した上で、LCS（最長共通部分列）により語順を考慮して単語単位で照合する |
| F-06-3 | 一致率（%）をスコアとして表示する。80% 以上 / 50% 以上 / 50% 未満の 3 段階で評価メッセージを変える |
| F-06-4 | 目標文を単語ごとに色分け表示する（一致＝緑、不一致＝赤）。認識候補 3 件のうち最高スコアを採用する |
| F-06-5 | 不一致だった単語について、Gemini から短い発音アドバイスを取得して表示する（重点スキルに「発音」を選んでいる場合はより詳しいアドバイス） |
| F-06-6 | **その日記における最初の発音チェック結果（スコア・不一致単語・認識テキスト）を保存し、2 回目以降のリトライでは上書きしない。** Step 6・過去日記詳細ページの両方で「📌 初回の結果」として常に確認でき、どこで発音を間違えたかを後から振り返れる |

### F-07 過去日記の閲覧

| ID | 要件 |
|----|------|
| F-07-1 | 保存済み日記を日付降順で一覧表示する（日付＋日本語冒頭プレビュー）。キーワード検索（日本語／英訳 1・2 回目／添削後英文を対象に部分一致）とページ送り（10/20/50/100 件から選択）に対応する |
| F-07-2 | 一覧のカードをタップすると日記詳細ページに遷移する（日本語 / 英訳 1 回目 / 2 回目 / AI 添削後 / カテゴリ別フィードバック / 初回発音結果、音声再生・発音再チェックボタン付き） |
| F-07-3 | 日記詳細ページから日本語・英訳 1・2 回目・添削後英文をインライン編集し、保存できる |

### F-08 日記の保存

| ID | 要件 |
|----|------|
| F-08-1 | 日付・日本語・英訳 1 回目・2 回目・添削後英文・AI フィードバック・初回発音チェック結果・`user_id` を `entries` テーブルに保存する。日本語未入力時は保存不可 |
| F-08-2 | ステップ③でメモした単語（日英とも入力済みのもの）、および AI フィードバックの語彙カテゴリで示された修正語彙を `vocab` テーブルへ自動追加する。英語表記の大文字小文字を無視して重複を除外する |
| F-08-3 | 保存後は全ステップ・初回発音結果を初期状態に戻し、追加された単語数を含む完了トーストを表示する |

### F-09 単語帳

| ID | 要件 |
|----|------|
| F-09-1 | 英語・日本語（必須）とメモ（任意）を手動で追加できる。既存の単語はその場で編集できる |
| F-09-2 | 登録単語を新しい順に一覧表示し、単語数・キーワード検索を提供する |
| F-09-3 | 各単語にテストの累計正答率を表示する（未テスト / 70% 以上＝良好 / 70% 未満＝要復習 の 3 区分で色分け） |
| F-09-4 | 単語を削除できる（確認ダイアログあり） |
| F-09-5 | すべての単語は `user_id` に紐づき、Row Level Security によって本人以外からは参照・変更できない |

### F-10 単語テスト（クイズ）

| ID | 要件 |
|----|------|
| F-10-1 | 出題対象・出題順は F-11（SRS）に基づく。単語ごとに日→英 / 英→日をランダムに決定する（リスニング形式は常に英→日） |
| F-10-2 | 出題形式として **タイピング回答（recall）・4 択（mc）・リスニング（listen、英語音声を聞いて和訳を入力）** の 3 形式をランダムに出し分ける。4 択の選択肢は単語帳内の他の単語からランダムに抽出する |
| F-10-3 | タイピング回答の判定は次の正規化・許容ルールに従う：trim・小文字化・NFKC 正規化・カタカナ→ひらがな変換、複数訳語（、 , / ・ ; 区切り）のいずれか一致で正解、英語は冠詞（a / an / the）を無視、5 文字以上の英語は編集距離 1 のタイポを正解扱い（タイポ注記付き） |
| F-10-4 | 正解 / 不正解を `vocab` の correct / wrong に即時反映するとともに、F-11 の SRS ステータス（`srs_stage`/`next_review_at`）を更新する |
| F-10-5 | 正解数・不正解数・残り問題数・連続正解数（streak）・進捗バーを常時表示し、正解時はカードにパルス演出、5 問ごとの連続正解でトースト通知を表示する。全問終了時に正答率を表示する |
| F-10-6 | ヒント（メモ欄の内容）の表示・非表示を切り替えられる。スキップした問題は末尾に回す |

### F-11 間隔反復（SRS）による出題スケジューリング

| ID | 要件 |
|----|------|
| F-11-1 | エビングハウスの忘却曲線を参考にした固定ステージ×日数（0 → 1 → 3 → 7 → 14 → 30 → 90 日）の簡易 Leitner 方式で、単語ごとに次回復習予定日（`next_review_at`）と習熟ステージ（`srs_stage`）を管理する |
| F-11-2 | 正解時はステージを 1 つ進め、次回復習日を該当ステージの日数だけ先に設定する。不正解時はステージを 2 つ戻す（下限 0） |
| F-11-3 | 出題キューは、復習期限が到来した単語を優先し、不足分は習熟ステージが低い（理解度が低い）単語ほど出やすい重み付けで補充する |
| F-11-4 | この出題プールは単語テスト（F-10）とシチュエーション文練習（F-12）の両方から共通で参照され、どちらの練習を行っても復習スケジュールが更新される |

### F-12 シチュエーション文練習

| ID | 要件 |
|----|------|
| F-12-1 | テストタブ内で「単語テスト」「状況文で練習」をトグルで切り替えられる。選択状態は次回アクセス時も維持する |
| F-12-2 | F-11 の SRS 出題プールから 1〜2 個の単語を選び、それらの単語を使わないと自然に答えられない日常シチュエーションの日本語文を Gemini に生成させ、対象単語をチップ表示する |
| F-12-3 | 回答は**発話（音声認識でテキスト化）**と**タイピング**の両方に対応する。どちらの方法で回答しても同じ AI 採点フローに合流する |
| F-12-4 | 回答は Gemini に送信し、文法的な正しさと対象単語の適切な使用有無を判定させる。判定結果（正誤・使用できた単語・添削文・一言フィードバック）を表示する |
| F-12-5 | 採点結果に応じて、使用できた単語は F-11 の SRS を正解として、使えなかった単語は不正解として更新する |

### F-13 UI 言語切り替え

| ID | 要件 |
|----|------|
| F-13-1 | ヘッダーのボタンで UI 言語を日本語 / 英語で切り替えられる |
| F-13-2 | 選択言語は localStorage に保存し、次回アクセス時も維持する |
| F-13-3 | 静的テキストは `data-i18n` / `data-i18n-placeholder` 属性と翻訳辞書（TRANSLATIONS）で一括切り替えする。AI フィードバック・発音アドバイス・シチュエーション文練習のフィードバックの言語も追従する（F-04-5） |

## 5. 非機能要件

| 分類 | 要件 |
|------|------|
| 費用 | すべて無料枠で運用する（GitHub Pages 無料 / Supabase 無料 500MB / Cloudflare Workers 無料枠 / Gemini API 無料枠 / Web Speech API はブラウザ内蔵） |
| 性能 | Gemini API 無料枠のレート制限内で動作する。レート超過時は自動リトライ（F-04-6） |
| 対応ブラウザ | Web Speech API（TTS・音声認識）に依存するため Chrome / Safari を推奨。音声認識非対応ブラウザでは該当機能のみ警告表示（他機能は利用可） |
| 対応端末 | レスポンシブ対応（viewport 設定済み）。PC・スマートフォンのブラウザで利用可能 |
| 可搬性 | フロントエンドはビルド不要の静的ファイル構成。Cloudflare Worker のみ別途デプロイが必要 |
| データ保全 | 学習データはすべて Supabase 上に保存され、複数端末から同一データにアクセスできる。Row Level Security により、ユーザーは自分のデータのみ参照・変更できる |
| XSS 対策 | ユーザー入力・AI 出力を画面表示する際は HTML エスケープを行う |

## 8. セキュリティ・制約事項

招待制・複数ユーザー運用を前提とした構成であり、以下を制約として許容している。

| ID | 内容 |
|----|------|
| C-01 | 新規ユーザーのセルフサインアップ経路はない。利用者を増やす場合は運用者が Supabase ダッシュボードから都度招待する必要がある |
| C-02 | Gemini API 呼び出し失敗時は元の英文をそのまま使う・エラーメッセージを添えるなどのフォールバックで最低限フローを継続できるようにしているが、AI 機能自体は Gemini の可用性に依存する |
| C-03 | 音声認識の精度はブラウザ実装に依存し、発音スコアはあくまで参考値（単語一致率であり、音素レベルの評価ではない） |
| C-04 | シチュエーション文練習の AI 採点は、Gemini が返す `used_target_words`（対象単語の使用有無）の文字列一致に基づいて SRS 更新の正誤を判定しており、活用形・言い換えの検出精度は Gemini の判定に依存する |

## 10. 用語集

| 用語 | 説明 |
|------|------|
| シャドーイング | 音声を聞きながら（または直後に）同じ英文を声に出して追いかける練習法 |
| TTS | Text-to-Speech。テキストの音声読み上げ |
| LCS | Longest Common Subsequence（最長共通部分列）。語順を考慮した単語列の一致度算出に使用 |
| NFKC 正規化 | Unicode 正規化形式の一つ。全角/半角などの表記ゆれを統一する |
| 編集距離（Levenshtein 距離） | 2 つの文字列を一致させるのに必要な最小の編集回数。タイポ許容判定に使用 |
| SRS | Spaced Repetition System（間隔反復）。忘却曲線に基づき復習タイミングを調整する学習法。本アプリではエビングハウスの忘却曲線を参考にした固定ステージ×日数の簡易 Leitner 方式を採用 |
| anon key | Supabase の匿名アクセス用公開 API キー |
| RLS | Row Level Security。PostgreSQL の行単位アクセス制御機能 |
| SPA | Single Page Application。単一の HTML で動作する Web アプリ |
